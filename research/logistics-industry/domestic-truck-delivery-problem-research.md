# 国内トラック配送の課題調査レポート

## このドキュメントの位置づけ

本ドキュメントは、配車計画支援システムを設計・実装するための前提として、国内トラック配送を取り巻く課題を整理するものである。
目的は、配送業界の問題を表面的な「ルート最適化」の話に閉じず、制度、労務、荷待ち、荷役、積載効率、荷主・着荷主との関係、日々の運用改善まで含めて理解することにある。後続の要件定義、基本設計、データモデル、最適化ロジック、運用設計は、この課題認識を前提に作成する。
結論として、国内トラック配送の課題は「最短ルートを計算できないこと」だけではない。より本質的には、ドライバーの労働時間制約、荷待ち・荷役時間、積載効率、発荷主・着荷主・物流事業者間の調整不足、契約外作業や追加費用の不透明さが重なった複合問題である。
したがって、本リポジトリで扱うシステムは、単なる経路探索アプリではなく、配送計画の実行可能性と改善余地を可視化する業務支援システムとして設計する。

## 1. 国内トラック配送を取り巻く大きな圧力

国内物流では、2024年4月からトラックドライバーにも時間外労働の年960時間上限規制と改正改善基準告示が適用されている。厚生労働省のポータルでは、2024年4月以降、時間外労働は臨時的特別な事情がある場合でも年960時間までと説明されている。また、拘束時間は年3,300時間以内を原則とし、例外でも年3,400時間以内、月拘束時間は原則284時間以内とされている。[1]
これは、配車計画において「運べるなら運ぶ」という発想が成立しにくくなっていることを意味する。ドライバーの拘束時間、休息期間、時間外労働上限を満たす計画だけが、実行可能な配送計画になる。
全日本トラック協会は、何も対策を行わなかった場合、営業用トラックの輸送能力が2024年には14.2%、2030年には34.1%不足する可能性があるという、国の「持続可能な物流の実現に向けた検討会」の試算を紹介している。[2]
この数字が示しているのは、問題が単なるコスト削減ではないということである。国内トラック配送では、ドライバー、車両、積載能力、荷役能力、発注リードタイム、納品時間帯といった限られた資源を前提に、安定供給を維持する必要がある。

## 2. 荷待ち・荷役は中核制約である

国土交通省が2026年7月に公表した「トラックドライバーの1運行当たりの平均拘束時間に関する調査結果」では、2025年度調査における1運行当たりの平均拘束時間は10時間13分、荷待ち・荷役等時間は2時間2分だった。前回2024年度調査と比較して、平均拘束時間は1時間33分減少し、その主因は荷待ち・荷役等時間が1時間16分減少したことだとされている。[3]
この数字から分かるのは、配送計画の改善余地は走行距離だけでは測れないということである。運転時間が大きく変わらなくても、荷待ち・荷役等時間が減れば、拘束時間は大きく短縮される。
厚生労働省の物流情報局は、新物効法における荷待ち時間を、到着時刻・時間帯の指定有無に応じて、到着または指定時刻から荷役開始までの時間として整理している。また、荷役等時間には、荷役、検品、荷造り、入出庫、棚入れ、仕分け、ラベル貼り、代金取立て・立替え、荷主等が行う荷役への立会いなど、運転業務に附帯する業務が含まれる。[4]
そのため、システム上も荷待ち・荷役を単なる備考として扱うべきではない。配送先ごとに、受付時間帯、想定荷待ち時間、想定荷役時間、バース制約、検品有無、パレット利用有無などを持たせる必要がある。

## 3. 政府が求める改善対象

2023年6月に経済産業省・農林水産省・国土交通省がまとめた「物流の適正化・生産性向上に向けた荷主事業者・物流事業者の取組に関するガイドライン」は、発荷主、物流事業者、着荷主が連携して取り組むべき事項を整理している。
同ガイドラインでは、荷待ち時間・荷役作業等にかかる時間の把握、荷待ち・荷役作業等時間を計2時間以内にすること、すでに2時間以内を達成している場合は1時間以内を目標にすることが示されている。[5]
また、長時間の荷待ちや、運送契約にない荷役作業等を物流事業者にさせてはならないことも示されている。中・大型トラックでは、荷主都合による荷待ち時間が30分以上あった場合や荷役作業、附帯業務を行った場合、乗務記録への記載が義務付けられている。[5]
この前提から、本システムで扱うべき改善対象は次のように整理できる。

| 改善対象システム上の扱い |                         |
| ------------ | ----------------------- |
| 荷待ち時間        | 配送先別の待機時間、時間帯別混雑、予約枠    |
| 荷役時間         | 荷姿、パレット有無、検品有無、作業人員     |
| 拘束時間         | ドライバー別の1日拘束時間、休息期間、月次上限 |
| 積載効率         | 車両容量、荷量、積載率、空車区間        |
| 発注リードタイム     | 当日依頼、前日依頼、定期便化          |
| 計画精度         | 予定と実績の差分、遅延・待機の原因分類     |

## 4. 積載効率は単純な容量充填率ではない

厚生労働省の物流情報局は、新物効法に基づく目標として、2028年度までに全国のトラック輸送のうち5割の運行で1運行当たりの荷待ち・荷役等時間を1時間短縮し、全国のトラック輸送のうち5割の車両で積載効率50%を目指すことを示している。これは全車両で積載効率を44%に増加することに相当すると説明されている。[6]
ただし、積載効率は単純な容量充填率だけではない。荷物には、重量、容積、荷姿、積み順、温度帯、配送順、時間指定、破損リスク、積み替え可否がある。車両の容量を満たしていても、配送順と積み順が矛盾すれば、現場では積み直しや荷役時間の増加が発生する。
したがって、初期実装では高度な3D積載までは扱わないとしても、少なくとも重量容量、容積容量、配送順と積み順の簡易制約、車両別積載率、空き容量、未割当荷物は扱う必要がある。
また、積載率を高めるほど拘束時間や荷役時間が悪化する場合もある。評価指標は単独ではなく、複数指標で比較する必要がある。

## 5. 問題は運送会社だけでは閉じない

公正取引委員会は、荷主による物流事業者に対する優越的地位の濫用を規制する観点から、荷主と物流事業者との取引状況を継続的に調査している。令和7年度調査では、独占禁止法上の問題につながるおそれのある行為を行った荷主779名に注意喚起文書を送付した。行為類型では「不当な給付内容の変更及びやり直し」「代金の支払遅延」「買いたたき」が多かった。[7]
同委員会は、製造工程の遅れや倉庫混雑により物流事業者に数時間または最大2時間程度の荷待ちをさせたにもかかわらず、追加費用の算定方法を定めておらず、追加費用も支払っていなかった事例を挙げている。[8] また、出荷日の変更や取消しにより人員・車両費用が発生しても補償しなかった事例、労務費等のコスト上昇を認識しながら協議の場を設けず運賃を据え置いた事例も示されている。[9]
ここから分かるのは、配送計画の失敗は運送会社の内部効率だけでは説明できないということである。荷主側の出荷準備遅れ、着荷主側の納品時間集中、バース混雑、急な変更、契約外作業、追加費用の未整理が、ドライバーの拘束時間と物流事業者の採算に直接影響する。
そのため、本システムでは、配送会社の配車係だけを対象にするのではなく、発荷主からの出荷予定、着荷主の受入可能時間、現場の荷役能力、実績フィードバックを扱える構造にする。

## 6. 課題仮説

一次情報から導ける課題仮説は次の通りである。

### 仮説1: 配送計画の主要課題は、走行距離の最短化だけではない

国内トラック配送では、ドライバーの拘束時間を規制内に収めながら、荷待ち、荷役、積載効率、納品時間を同時に管理する必要がある。国土交通省調査では、荷待ち・荷役等時間の減少が拘束時間短縮の主因になっており、ルート以外の時間管理に大きな改善余地がある。[3]

### 仮説2: 配送計画の精度は、荷主・着荷主との情報連携に依存する

公正取引委員会の事例では、出荷準備遅れ、事務手続遅れ、バース混雑、集荷時刻調整不足が、荷待ちや追加費用未払いにつながっている。[8] そのため、システムが扱う入力は、配送先住所と荷量だけでは足りない。

### 仮説3: 改善は一回の最適化ではなく、運用サイクルで進む

公正取引委員会が挙げた良い取組例では、荷主が前日に緻密な配車表を作成して物流事業者に提示し、問題がないか確認して翌日の配車を確定し、事後検証を繰り返して配車計画の精度を高めたことで、荷主起因の荷待ちをほとんどなくしたとされている。[10]
これは、本システムが「最適化ボタン」だけで完結してはいけないことを示している。計画、確認、実行、実績入力、差分分析、改善の運用サイクルを支援する必要がある。

## 7. システム要件へ変換すべき制約

国内トラック配送を題材にしたシステムでは、少なくとも以下の制約を扱う必要がある。

| 制約カテゴリ具体例要件化の方向 |                        |                          |
| --------------- | ---------------------- | ------------------------ |
| 労務制約            | 年960時間の時間外上限、拘束時間、休息期間 | ドライバー別の稼働可能時間、拘束時間超過アラート |
| 運行制約            | 運転時間、休憩、長距離運行、渋滞       | 移動時間、休憩挿入、到着予定時刻         |
| 荷待ち制約           | 受付待ち、バース混雑、予約枠         | 配送先別の想定待機時間、予約スロット       |
| 荷役制約            | 積込み、荷卸し、検品、棚入れ、附帯作業    | 作業時間、作業種別、作業者・フォークリフト有無  |
| 積載制約            | 重量、容積、荷姿、積み順           | 車両容量、荷量、積載率、積み順簡易制約      |
| 商流制約            | 発荷主、着荷主、元請、下請          | 依頼元、納品先、契約条件、追加費用        |
| 変更制約            | 当日キャンセル、時間変更、出荷遅れ      | 再計画、差分表示、追加費用候補          |
| 評価制約            | 総距離、拘束時間、遅延、積載率、待機時間   | 複数指標の比較、改善・悪化の見える化       |

この制約表を前提にすることで、作るものは単純な地図アプリではなく、配車計画の意思決定支援システムになる。

## 8. 本リポジトリで扱う問題設定

本リポジトリでは、次の問題設定を採用する。

> 国内トラック配送では、ドライバーの労働時間制約が強まる一方で、荷待ち・荷役・積載効率・発注/納品タイミング・契約外作業が複合的に拘束時間と輸送能力を圧迫している。したがって、配送計画は走行距離だけでなく、荷待ち・荷役・積載率・時間指定・拘束時間・追加費用を同時に見ながら、計画、実行、実績、改善を回す必要がある。

この問題設定に基づき、初期スコープでは次のテーマを扱う。

> 荷待ち・荷役・積載率・拘束時間を含めて、配送計画の実行可能性と改善余地を可視化する配車計画支援システム

## 9. MVPで扱う機能

MVPでは、最初から高精度な道路交通予測や実住所のジオコーディングには寄せすぎない。まずは架空の配送先座標、距離行列、時間窓、荷役時間、車両容量、ドライバー稼働時間を使い、制約付き配車問題として再現する。

| 機能目的       |                                |
| ---------- | ------------------------------ |
| 配送依頼登録     | 配送先、荷量、希望時間帯、荷役条件を入力する         |
| 車両・ドライバー登録 | 車両容量、稼働時間、拘束時間上限を設定する          |
| 配送先別制約管理   | 受付時間、想定荷待ち、想定荷役、バース制約を持たせる     |
| 配車計画作成     | 車両別の配送順と到着予定を作る                |
| 実行可能性チェック  | 拘束時間超過、時間指定違反、積載超過を検出する        |
| 評価指標表示     | 総距離、総拘束時間、荷待ち、荷役、積載率、遅延件数を比較する |
| 手動調整       | 配送順や割当を変えた際の改善・悪化を表示する         |
| 実績入力       | 実際の到着、荷待ち、荷役、出発時刻を記録する         |
| 振り返り       | 予定と実績の差分、荷待ち原因、次回改善案を残す        |

## 10. 初期データセットに入れる現実由来の条件

初期データセットには、以下の条件を入れる。

| パラメータ初期値・考え方根拠 |                             |                          |
| -------------- | --------------------------- | ------------------------ |
| 1運行の平均拘束時間     | 10時間13分を現状平均の参照値にする         | 国交省2025年度調査[3]           |
| 荷待ち・荷役等時間      | 平均2時間2分、目標2時間以内             | 国交省2025年度調査、ガイドライン[3][5] |
| 荷待ち・荷役短縮目標     | 1運行あたり1時間短縮を改善目標に置く         | 新物効法に基づく目標[6]            |
| 積載効率目標         | 車両単位50%、全車両44%相当を参照値にする     | 新物効法に基づく目標[6]            |
| 荷待ち記録単位        | 30分以上の荷主都合待機を要注意イベントにする     | ガイドライン[5]                |
| 労働時間上限         | 年960時間の時間外労働上限、年拘束3,300時間原則 | 厚労省改善基準告示[1]             |
| 目標時間           | 荷待ち・荷役計2時間以内、可能なら1時間以内      | ガイドライン[5]                |

評価指標は、少なくとも以下の複数軸にする。

| 指標意味     |                   |
| -------- | ----------------- |
| 総走行距離    | 燃料費・車両稼働の効率       |
| 総拘束時間    | ドライバー労務制約への影響     |
| 荷待ち時間    | 荷主・着荷主起因の非効率      |
| 荷役等時間    | 作業設計・荷姿・検品の負荷     |
| 積載率      | 車両資源の利用効率         |
| 時間指定違反件数 | サービス品質            |
| 再計画回数    | 計画安定性             |
| 追加費用候補   | 待機・変更・附帯作業のコスト顕在化 |

## 11. 対象外とするもの

初期実装では、以下は対象外とする。

| 対象外理由        |                        |
| ------------ | ---------------------- |
| 実住所のジオコーディング | 初期段階では業務制約の再現を優先するため   |
| リアルタイム交通情報   | 最初は距離行列と時間係数で近似するため    |
| 高精度な3D積載     | まずは重量・容積・簡易積み順制約で十分なため |
| 完全自動配車       | 現実の運用では手動調整と確認が必要なため   |
| 荷主・着荷主向け外部連携 | MVP後の拡張テーマとするため        |

## 12. 暫定結論

国内トラック配送の課題は、最短ルートを計算するだけでは解けない。
本リポジトリで扱うべき中心課題は、荷待ち・荷役・積載率・拘束時間・納品時間帯・追加費用候補を含めて、配送計画の実行可能性と改善余地を可視化することである。
そのため、初期実装では以下を重視する。

- 走行距離だけでなく、拘束時間、荷待ち、荷役、積載率を同時に見る
- 配送先ごとの制約をデータとして保持する
- 計画と実績の差分を記録し、改善サイクルを回せる構造にする
- 最適化結果を絶対視せず、手動調整後の改善・悪化を比較できるようにする
- 荷主・着荷主起因の待機や変更も、計画上の制約として扱う

この前提により、後続の要件定義・設計では、単なるルート最適化ではなく、現実の配送業務に近い制約付きの配車計画支援システムを目指す。

   新物効法における荷待ち時間・荷役等時間の定義、荷役等に含まれる業務範囲を確認するために参照した。荷待ち・荷役を配送計画上の時間項目として扱う根拠とした。

5. 経済産業省・農林水産省・国土交通省. [物流の適正化・生産性向上に向けた荷主事業者・物流事業者の取組に関するガイドライン](https://www.mlit.go.jp/report/press/content/001612798.pdf). 2023年6月.
   荷待ち時間・荷役作業等時間を計2時間以内にすること、さらに1時間以内を目標にすること、荷主都合による30分以上の荷待ち等の記録義務、契約外の荷役作業をさせてはならないことを参照した。システム上のアラート条件、目標値、記録対象イベントの設定根拠とした。

6. 厚生労働省. [物流情報局（荷主の皆さまへ）](https://driver-roudou-jikan.mhlw.go.jp/truck/shipper).
   新物効法に基づく対応事項として、2028年度までに全国のトラック輸送のうち5割の運行で1運行当たりの荷待ち・荷役等時間を1時間短縮する目標、および5割の車両で積載効率50%を目指す目標を参照した。MVPにおける改善目標と評価指標の根拠とした。

7. 公正取引委員会. [(令和8年6月25日)令和7年度における荷主と物流事業者との取引に関する調査結果等について](https://www.jftc.go.jp/houdou/pressrelease/2026/jun/260625_buttokuchousakekka.html).

8. 公正取引委員会. [(令和8年6月25日)令和7年度における荷主と物流事業者との取引に関する調査結果等について](https://www.jftc.go.jp/houdou/pressrelease/2026/jun/260625_buttokuchousakekka.html).
   製造工程の遅れ、倉庫混雑、集荷時刻の調整不足などにより荷待ちが発生したにもかかわらず、追加費用の算定方法を定めておらず、費用も支払っていなかった事例を参照した。荷主・着荷主起因の遅延や待機を、配車計画上の制約・追加費用候補として扱う根拠とした。

9. 公正取引委員会. [(令和8年6月25日)令和7年度における荷主と物流事業者との取引に関する調査結果等について](https://www.jftc.go.jp/houdou/pressrelease/2026/jun/260625_buttokuchousakekka.html).
   出荷日の変更・取消しに伴う人員費用・車両費用の未補償、労務費等のコスト上昇を認識しながら協議の場を設けず運賃を据え置いた事例を参照した。計画変更、再計画、追加費用、契約条件をシステム上の論点に含める根拠とした。

10. 公正取引委員会. [(令和8年6月25日)令和7年度における荷主と物流事業者との取引に関する調査結果等について](https://www.jftc.go.jp/houdou/pressrelease/2026/jun/260625_buttokuchousakekka.html).
    荷主が前日に緻密な配車表を作成し、物流事業者と確認したうえで翌日の配車を確定し、事後検証を繰り返すことで荷主起因の荷待ちを削減した好事例を参照した。本システムで、計画作成だけでなく、確認、実績入力、差分分析、改善サイクルを扱う根拠とした。
